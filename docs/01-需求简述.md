# 需求简述｜SaaS 统一运营与分销管理中台

> 版本 V3.0 · 日期 2026-11-20  
> 完整方案：[方案-SaaS统一运营与分销管理中台-V3.0.md](./方案-SaaS统一运营与分销管理中台-V3.0.md)  
> 历史方案：[方案-SaaS底座-权益中台-V2.0.md](./方案-SaaS底座-权益中台-V2.0.md)

## 1. 建设目标

建设一套供多个业务系统共同使用的 SaaS 管理中台。首批接入 ShareDAO、AI Smart 儿童英语、数字商品商店、CertReport AI。

平台统一管理：
1. 身份：Account、登录身份、会话、SSO。
2. 租户：Tenant、Workspace、Membership、组织角色与权限。
3. 应用：Application、TenantApp、应用授权与接入凭证。
4. 商业化：产品目录、套餐、订阅、订单、支付、退款、发票。
5. 账户：现金钱包、积分、AI/功能额度、权益包及各自账本。
6. 分销：SaaS 渠道商、业务推广伙伴、客户归属、佣金与结算。
7. 运营：用量计量、配额、风控、审计、报表、开放 API。

业务系统保留自己的业务数据和业务流程，通过 SSO、权益校验、用量上报和事件回调接入。

## 2. 核心对象规则

- Account 是全局唯一登录身份；手机号、邮箱、微信等作为 AccountIdentity。
- Tenant 是客户组织与数据隔离边界。
- Membership 表示 Account 在 Tenant 中的成员关系；角色挂在 Membership。
- 一个 Account 可加入多个 Tenant；一个 Tenant 可开通多个 Application。
- TenantApp 表示租户开通的应用实例；Subscription 绑定 TenantApp。
- 平台订阅、现金钱包、积分、AI额度、功能权益、分销佣金分账管理。
- SaaS 渠道分销与业务商品推广分为两套 Partner、佣金政策和结算域。

## 3. 分期优先级

| 阶段 | 范围 | 验收目标 |
|---|---|---|
| P0 | Account、Identity、Tenant、Membership、RBAC、Application、TenantApp、SSO、审计、租户隔离 | 两个业务应用、两个租户接入，跨租户访问拒绝 |
| P1 | Plan、Feature、Price、Subscription、订单支付退款、Entitlement、Usage Credit、用量计量 | 套餐购买后权益生效，退款和额度扣减正确 |
| P2 | 积分规则与账本、兑换履约、SaaS 渠道、Affiliate 推广、佣金结算 | 渠道推荐订阅可结佣，业务推广订单独立结佣 |
| P3 | 多币种、按量计费、渠道层级、私有化授权、租户迁移 | 支持规模化运营 |

## 4. 关键约束

- 所有租户数据必须有可验证的 tenantId 归属；租户上下文来自服务端验证，不信任请求体。
- 所有账本不可变；调整和退款通过反向流水；支付、退款、积分、额度、佣金、兑换必须幂等。
- 金额使用 Decimal；费率使用 Decimal 或整数基点，禁止财务计算使用 Float。
- 使用 Outbox/Inbox、Webhook 签名、重试、死信与人工重放。
- 业务 App 的订单和学习数据留在业务系统；中台只接收完成商业结算所需的事件摘要。
- 儿童学习明细不得向 Partner 或渠道商开放。

## 5. 本期不做

首期不做多级分佣、复杂财务总账、现金钱包提现、多币种税务、微服务拆分。模型可预留扩展点，启用前单独评审。
